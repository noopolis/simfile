# Simfile Viewer

This folder contains the browser UI for replaying Simfile run records.

## Structure

- `App.tsx` owns data loading, stream subscription, selection state, and the console shell for world/live replay. `../main.tsx` selects it by `/api/state.mode`; do not add run-replay branching inside this file.
- `RunReplayShell.tsx` is the sibling shell for run-replay mode (a sealed compose-and-observe run directory): the same `AsciiMap`/`worldModel`/`renderSettings` map, `ReplayPanes.tsx`'s chat/minds panes, a stack of `../portals/StorylinePortal.tsx` (one per entry in `../store/timeline.ts`'s `openPortals`), `RunMetaPanels.tsx`'s verdict strip/provenance drawer/spread readout/variable gauge, and `../chrome/ScrubBar.tsx` as global chrome — all reading the one `timelineStore` cursor. It loads `/api/timeline`, `/api/world`, and `/api/run-meta` itself; it does not touch `/api/events` (run-replay has no live SSE tick). It also owns deep-link wiring: `../store/deepLink.ts`'s `applyDeepLink` restores `?at=&sel=&portals=` once the timeline loads, and `startDeepLinkSync` mirrors store changes back into the URL. Increment 3: derives `utteredEventIds`/`seedSpreadEventIds`/`glowScopes` from `runMeta` + the timeline (via `spreadModel.ts`) and passes them into `ChatPane`, `ScrubBar`, and `AsciiMap` respectively — all empty/undefined when the run has no seed declaration. Increment 4: derives `variableTick` (`variableModel.ts`'s `tickAtCursor` — the world clock's own tick "as of" the scrub cursor) once here and passes it, plus `runMeta?.variableSamples`, into `VariableGaugeRail` and every open `StorylinePortal` (as `variableSamples`/`variableTick` props) so a `variable:<id>` portal can render its own trajectory panel without re-deriving the tick join.
- `ReplayPanes.tsx` — the room-chat pane and the minds rail, split out of `RunReplayShell.tsx` to keep that file focused on layout/data-loading. The chat pane renders `RecallChips` under any `turn.input` chip; the minds rail groups memory events by bank then by agent, and every bank/agent header opens its storyline portal through `focusAndOpenPortal` — the same mechanism the map and chat use, never a bespoke open path. Increment 3: `ChatPane` filters out a `world`-authority message whose id is in `../store/timeline.ts`'s `echoedWorldEventIds` (its moltnet echo already renders, badged "world"); a `world`-authority message that survives the filter renders standalone, flagged "not delivered"; a message whose id is in the passed-in `utteredEventIds` gets the "🧬 seed" badge.
- `RunMetaPanels.tsx` — `VerdictStrip` (compact topbar readout) and `ProvenancePanel` (artifact sha/ok + reconciliation entries drawer), rendering the `/api/run-meta` JSON that `computeVerdict`/`computeProvenance` (`src/view/runViewModelCompute.ts`) already produce — parity with the retired bespoke run page, not a reimplementation. Increment 3 adds `SpreadReadout` (reach/latency/first-appearance from `spreadSummary`, never recomputed). Increment 4 completes `VariableGaugeRail`: given `samples` (`variableSamples`) and `tick` (the caller's own `tickAtCursor` join) it renders each variable's value-at-cursor (`variableModel.ts`'s `sampleAtTick`) plus a small `VariableSparkline` of its trajectory up to that tick (`trajectoryUpToTick` — never a future sample); each chip is a button calling the passed-in `onSelectVariable` (never importing the timeline store directly, matching `VerdictStrip`'s `onOpenProvenance` callback pattern) so `RunReplayShell` can wire it to `focusAndOpenPortal`. Still renders `null` when there is no non-empty `variableSamples` or the cursor is before the run's first `clock.sync`. `VariableSparkline` is exported so `../portals/StorylinePortal.tsx`'s trajectory panel reuses the exact same mark, not a second sparkline implementation.
- `variableModel.ts` — the variable gauge/storyline's pure join layer (increment 4), the same role `spreadModel.ts` plays for seed spread: `RunMetaVariableSample` (the `world/telemetry.json` sample shape, re-exported from `RunMetaPanels.tsx` for back-compat), `tickAtCursor` (the world clock's own tick "as of" the scrub cursor, read from the timeline's own `clock.sync` events — never a derived/invented tick), `sampleAtTick` (the telemetry sample "as of" a tick), and `trajectoryUpToTick` (one variable's value series up to and including a tick — the sparkline series). No UI; `RunMetaPanels.tsx`, `RunReplayShell.tsx`, and `../portals/StorylinePortal.tsx` all call these rather than re-deriving the tick/sample joins inline.
- `spreadModel.ts` — pure joins between `/api/run-meta`'s `seedSpread`/`spreadSummary` and a loaded `RunTimeline`: `seedSpreadEventIds`/`utteredEventIds` (the scrub-bar dots / chat seed badge sets) and `firstAppearanceGlowScopes` (the map-glow scopes, gated on the cursor reaching each first-appearance event's own real `t`). No UI; `ReplayPanes.tsx`, `RunMetaPanels.tsx`, and `RunReplayShell.tsx` all call these rather than re-deriving the joins inline.
- `worldModel.ts` converts the generated `viewer-trace.json` contract (world/live) or the `runWorldTrace` adapter's output (run-replay) into render-ready nodes, rooms, paths, and event rows — both feed the same function unchanged.
- `tileWorld.ts` derives a viewer-owned tile/glyph world model from run artifacts so presentation can stay separate from the data.
- `AsciiMap.tsx` renders the default replay console surface: a dense ASCII/tile map with room, corridor, signal, and agent layers. Increment 3's optional `glowScopes` prop (a set of node `scope`s) renders the matching tile cell(s)/anchor with the pulsing "glow" class — the seeded meme's first-appearance highlight; omitted/empty renders no glow at all.
- `SceneMap.tsx`, `SceneGeometry.tsx`, `SceneLabels.tsx`, `CameraFocus.tsx`, and `sceneMotion.ts` are retained while the console transitions away from the pseudo-3D surface.
- `RenderSettingsPanel.tsx` and `renderSettings.ts` define runtime visual controls.
- `types.ts` is the shared contract between the viewer server, trace artifact, and React components.

## Constraints

- Do not add Simfile authoring keys for presentation. Viewer skins and layout are derived from run artifacts or viewer-owned configuration.
- Replay mode must render the run trace it was given. Do not silently fall back to demo data when `/api/world` is unavailable.
- Heuristic agents may be listed in the inspector, but they are not rendered as room bodies unless the trace has presence events for them.
- Keep the tile world data-first. The flat console is the first presentation of that model, not the only possible renderer.
- Keep components focused and split before files approach 400 lines.
