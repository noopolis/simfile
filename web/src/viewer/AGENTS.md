# Simfile Viewer

This folder contains the browser UI for replaying Simfile run records.

## Structure

- `App.tsx` owns data loading, stream subscription, selection state, and the console shell for world/live replay. `../main.tsx` selects it by `/api/state.mode`; do not add run-replay branching inside this file.
- `AppRows.tsx` owns the small reusable panel, node-row, and event-row renderers
  used by the world/live shell.
- `RunReplayShell.tsx` is the sibling shell for run-replay mode (a sealed compose-and-observe run directory): the same `AsciiMap`/`worldModel`/`renderSettings` map, `ReplayPanes.tsx`'s chat/minds panes, a stack of `../portals/StorylinePortal.tsx` (one per entry in `../store/timeline.ts`'s `openPortals`), `RunMetaPanels.tsx`'s engine-provenance badge/verdict strip/provenance drawer/spread readout/variable gauge, and `../chrome/ScrubBar.tsx` as global chrome — all reading the one `timelineStore` cursor. It loads `/api/timeline`, `/api/world`, and `/api/run-meta` itself; it does not touch `/api/events` (run-replay has no live SSE tick). It also owns deep-link wiring: `../store/deepLink.ts`'s `applyDeepLink` restores `?at=&sel=&portals=&panel=` once the timeline loads, and `startDeepLinkSync` mirrors store changes back into the URL. `ReplayPrimaryPane.tsx` switches the primary surface between Conversation and Map; `replayPanel.ts` selects Conversation only when the complete sealed timeline contains a nonblank message admitted by the exact participant chat projection. An explicit URL panel or existing user choice wins, and default selection runs once so a cursor move or live seal cannot clobber it. Increment 3: derives `utteredEventIds`/`seedSpreadEventIds`/`glowScopes` from `runMeta` + the timeline (via `spreadModel.ts`) and passes them into `ChatPane`, `ScrubBar`, and `AsciiMap` respectively — all empty/undefined when the run has no seed declaration. Increment 4: derives `variableTick` once through `variableModel.ts`'s delegating `tickAtCursor` and passes that same record-owned whole world tick to `AsciiMap`, `ActionFeedPane`, `VariableGaugeRail`, and every open `StorylinePortal` (as the unchanged `variableTick` prop), so no consumer re-derives the cursor join; it remains `undefined` for a record that states no time. Honesty-gap fix: renders `EngineProvenanceBadge` in the topbar right after the run name and before the verdict strip — placement, not just styling, is what makes it unmissable — from `runMeta.engineProvenance`, which is never undefined (see `RunMetaPanels.tsx`/`src/view/engineProvenance.ts`).
- `runLifecycle.ts` loads the atomic post-seal timeline/world/meta response used
  to replace every live-pending fact in one client update.
- `runLiveClient.ts` owns the generic temporary timeline and SSE parser used
  only while an append-only run record remains open.
- `spatialReplayTimeline.ts` supplies the one global cursor for a sealed
  spatial-only record only when its real causal timeline is empty. Its neutral
  `spatial.sample` rows carry recorded simulated ticks from the viewer trace
  and never replace causal events.
- `ReplayPanes.tsx` — the minds rail and the compatibility re-export for `ChatPane`. The rail groups memory events by bank then by agent; recorded action principals render as compact one-line rows whose details open in a modal, keeping the map-adjacent rail stable. Every bank/agent header opens its storyline portal through `focusAndOpenPortal` — the same mechanism the map and chat use, never a bespoke open path.
- `ChatPane.tsx` — participant-only room chat. It admits nonblank messages only when their actor is an agent declared by the timeline, so world/control-plane records never appear as chat; it keeps recall chips, membrane treatment, world-echo badges on participant speech, and seed badges.
- `actionFeed.ts` — the pure, genre-neutral join primitives over the action attempt/result events already present in `RunTimeline`: the `ActionFeedRow` shape, `joinRecordedActions` (attempt joined to its own result by the run's `act_id`), `summarizeActions`, and `participantRef`, which resolves a recorded participant only to an element ref the timeline enumerates. The module never reads or serves a second action stream.
- `actionLog.ts` — the action feed as an APPEND LOG, the prefix convention `ReplayPanes.tsx`'s `ChatPane`/`MindsRail` and `../portals/StorylineRows.tsx` already read. `buildActionLog` orders every recorded action and commitment resolution ONCE per timeline (by tick, then the run's own ordering key, then source position); `actionLogUpToTick` answers a cursor with a binary search and a slice — the log does not move with the cursor, so a cursor change never rescans the event stream (B206). A resolution entry carries an `ActionLogDeclaration`: the declarer, the body declared through, the verb, the target and the tick it was declared at, so an outcome is readable on its own however far below its declaration it lands. `actionsAtTick` remains as the single-query exact-tick slice; a cursor-moving caller must build the log once instead.
- `actionNarration.ts` — the generic action presentation vocabulary: structural display names and declaration facts, plus the record-decider axis shared by tests, category derivation, and rendering. `actionDecider` derives declared/derived/refused from the record's stated `provenance`, rejection outcome, and compatibility phase fallback; it never switches on an action name.
- `actionNarrators.ts` — the in-process action-narrator catalog and its viewer-local narration contract. Narrators can distinguish one-line records from wrapping message content; the public fixture contract cannot request message form until its separately declared type is extended outside B279's lane.
- `actionFeedCategories.ts` — derives the stable filter set from the whole action log as record-decider-plus-recorded-verb keys, humanizes only the recorded verb, counts the cursor prefix, and filters entries by hidden keys. It contains no scenario category enumeration.
- `ActionFeedRows.tsx` — the fixed-column action and standing-commitment rows used by the pane. It renders the shared glyph-plus-word role chips, keeps actor/focus semantics aligned with the record-decider role, and puts every structured row's secondary context behind a native disclosure while narrator-authored message form may wrap in full.
- `ActionFeedPane.tsx` — builds the append log, its whole-run derived category set, and standing spans once per timeline; counts and filters the visible prefix at the cursor, reports hidden rows, and delegates symmetric row rendering to `ActionFeedRows.tsx`.
- `commitmentSpans.ts` — the same records read as SPANS rather than instants. A commitment opens at the accepted declaration and closes at the `dynamics.commitment.outcome` the run joined to it by declaration sequence; `commitmentsInForceAtTick` answers what a participant is on the hook for at the cursor, which is what an observer scrubbing a long run needs to see. A declaration the run never terminated is reported standing — never given an invented outcome. `ActionFeedPane.tsx` renders these spans first (built once per timeline, then filtered by `commitmentSpanInForceAt`) and `actionLog.ts`'s accumulating log underneath, scrolled to the newest entry.
- `RunMetaPanels.tsx` — `VerdictStrip` (compact topbar readout) and `ProvenancePanel` (artifact sha/ok + reconciliation entries drawer), rendering the `/api/run-meta` JSON that `computeVerdict`/`computeProvenance` (`src/view/runViewModelCompute.ts`) already produce — parity with the retired bespoke run page, not a reimplementation. Increment 3 adds `SpreadReadout` (reach/latency/first-appearance from `spreadSummary`, never recomputed). Increment 4 completes `VariableGaugeRail`: given `samples` (`variableSamples`) and `tick` (the caller's own `tickAtCursor` join) it renders each variable's value-at-cursor (`variableModel.ts`'s `sampleAtTick`) plus a small `VariableSparkline` of its trajectory up to that tick (`trajectoryUpToTick` — never a future sample); each chip is a button calling the passed-in `onSelectVariable` (never importing the timeline store directly, matching `VerdictStrip`'s `onOpenProvenance` callback pattern) so `RunReplayShell` can wire it to `focusAndOpenPortal`. Still renders `null` when there is no non-empty `variableSamples` or the cursor is before the run's first `clock.sync`. `VariableSparkline` is exported so `../portals/StorylinePortal.tsx`'s trajectory panel reuses the exact same mark, not a second sparkline implementation. The honesty-gap fix adds `EngineProvenanceBadge`: renders `meta.engineProvenance.label` verbatim (already worded unambiguously by `src/view/engineProvenance.ts` — "authored screenplay, not emergent dialogue" for scripted, the engine name for real) in a `.engine-badge-<mode>`-classed span (`scripted`/`real-engine`/`mixed`/`unknown`, styled in `../styles-replay.css`); its `title` attribute lists the full per-agent engine breakdown. Never renders a softened/shortened version of the label — this is the one place in the app that must over-disclose rather than under-disclose.
- `variableModel.ts` — the variable gauge/storyline's pure join layer (increment 4), the same role `spreadModel.ts` plays for seed spread: `RunMetaVariableSample` (the `world/telemetry.json` sample shape, re-exported from `RunMetaPanels.tsx` for back-compat), `recordedTickOf` (the kind-specific tick a timeline event explicitly states), `recordedTickAtCursor` (the scan used only when no corroborated clock exists), `tickAtCursor` (the consumer accessor that delegates to the mapping owner before that fallback), `sampleAtTick` (the telemetry sample "as of" a tick), and `trajectoryUpToTick` (one variable's value series up to and including a tick — the sparkline series). No UI; `RunMetaPanels.tsx`, `RunReplayShell.tsx`, and `../portals/StorylinePortal.tsx` all call these rather than re-deriving the tick/sample joins inline.
- The cursor→tick mapping lives in `../chrome/playbackCadence.ts`; `variableModel.tickAtCursor` is its one consumer-side accessor and falls back to its own recorded scan only for records with no corroborated clock. Every tick-aware viewer consumes the shell's one computed value rather than introducing another mapping.
- `spreadModel.ts` — pure joins between `/api/run-meta`'s `seedSpread`/`spreadSummary` and a loaded `RunTimeline`: `seedSpreadEventIds`/`utteredEventIds` (the scrub-bar dots / chat seed badge sets) and `firstAppearanceGlowScopes` (the map-glow scopes, gated on the cursor reaching each first-appearance event's own real `t`). No UI; `ReplayPanes.tsx`, `RunMetaPanels.tsx`, and `RunReplayShell.tsx` all call these rather than re-deriving the joins inline.
- `worldModel.ts` converts the generated `viewer-trace.json` contract (world/live) or the `runWorldTrace` adapter's output (run-replay) into render-ready nodes, rooms, paths, and event rows — both feed the same function unchanged. It may also preserve manifest-authenticated extension JSON as opaque data; only the selected extension may interpret it.
- `tileWorld.ts` derives a viewer-owned tile/glyph world model from run artifacts so presentation can stay separate from the data.
- `AsciiMap.tsx` renders the default replay console surface: a dense ASCII/tile map with room, corridor, signal, and agent layers. Its optional `tick` is a simulated world tick, never the event-index scrub cursor; when absent, it renders bodies at declared room anchors with no spatial/presence overlay or motion claim, while a documented numeric geometry seed satisfies the renderer-host contract without presenting tick 0 as observed. Increment 3's optional `glowScopes` prop (a set of node `scope`s) renders the matching tile cell(s)/anchor with the pulsing "glow" class — the seeded meme's first-appearance highlight; omitted/empty renders no glow at all.
- `SceneMap.tsx`, `SceneGeometry.tsx`, `SceneLabels.tsx`, `CameraFocus.tsx`, and `sceneMotion.ts` are retained while the console transitions away from the pseudo-3D surface.
- `RenderSettingsPanel.tsx` and `renderSettings.ts` define runtime visual controls.
- `types.ts` is the shared contract between the viewer server, trace artifact, and React components.

## Constraints

- Do not add Simfile authoring keys for presentation. Viewer skins and layout are derived from run artifacts or viewer-owned configuration.
- Replay mode must render the run trace it was given. Do not silently fall back to demo data when `/api/world` is unavailable.
- Heuristic agents may be listed in the inspector, but they are not rendered as room bodies unless the trace has presence events for them.
- Keep the tile world data-first. The flat console is the first presentation of that model, not the only possible renderer.
- Extension frames may receive the existing timeline cursor and generic
  `unsealed/local` or `recorded` identities. The shell must not translate that
  cursor into a scenario clock or inspect scenario-specific payload fields.
- Keep components focused and split before files approach 400 lines.
